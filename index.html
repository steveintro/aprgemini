Executive Summary

What This Is & Why It Matters

Project communication is scattered across individual inboxes with no shared source of truth. This pipeline changes that.

⚡
The Problem
Project emails land in individual inboxes. Phase handoffs are verbal. Status lives in people's heads. There's no consistent record of what's active, who owns what, or what savings were captured.
🧠
The Solution
A Gemini-powered chat intake tool creates standardized project records. Automated email processing keeps those records updated across all team members using Gmail thread ID deduplication.
💰
Savings Intelligence
A dedicated savings validation tool reviews bids against APR benchmarks and outputs structured findings — attached to the project record, feeding directly into ACERO reporting.
📊
The Outcome
A live dashboard visible to all stakeholders showing every active project, current phase, owner, last activity, and validated savings. No manual updates. No version control issues.
Infrastructure

Why We Need Vertex AI

Enterprise Gemini in Workspace (Gmail, Docs, Gems) is a UI layer — it can't power an automated pipeline or handle client data outside its chat interface. Vertex AI is the API layer that makes this buildable.

Requirement Without Vertex AI With Vertex AI
Powering the AI pipeline ✗ Personal API key — data leaves enterprise boundary ✓ Enterprise-credentialed API calls within Google Cloud
Multi-user access ✗ Each user needs their own credentials ✓ One service account, all users authenticate via Workspace login
Client data governance ✗ No guarantee of where client data goes ✓ Google Cloud enterprise DPA applies — data stays inside APR's agreement
Usage visibility & audit ✗ No audit trail ✓ All API calls logged, billed to one corporate Cloud project
Apps Script integration ✗ Manual credential management per user ✓ Service account authenticates on behalf of all scripts
Future scaling ✗ Ad hoc personal tooling, not shareable ✓ Production-grade, IT-managed, expandable to any client or team
What to ask IT: "Does our enterprise Workspace license include Vertex AI or Google Cloud access for internal tool development?" The key product is Vertex AI on Google Cloud — this is separate from the Workspace UI features most teams use.

Intake Tool

The Chat Intake Experience

A Gem-like conversational interface built as an Apps Script web app. Colleagues open it in a browser, authenticated via their Workspace login. No separate credentials, no training required.

01
Open the tool
Team member opens the Apps Script web app in any browser — authenticated automatically via Google Workspace login. No separate credentials or accounts required.
02
Gemini guides the intake conversation
AI prompts the user through: client (from fixed list), brand, project type, deliverables, timeline, PO number, phase owner, team members. Fixed options enforce naming consistency — no free-text client names that drift.
03
Confirm the summary
Gemini presents a full structured summary before writing anything. User confirms or corrects. Nothing fires until approved.
04
Pipeline fires automatically
Tool writes a JSON record to the shared Drive inbox folder. The watcher script detects the new file, creates the Drive folder structure, Gmail label, and Sheet row — all in one automated sequence.
05
Phase handoff notification sent
When a phase is marked complete, the next phase owner receives a notification with the exact label name pre-filled. No lookup, no risk of naming error. If someone is pulled in mid-project, the same tool offers a project lookup mode to retrieve the label instantly.
Multi-User Logic

Teams, Phases & Deduplication

Multiple people on the same project, emails going to everyone, phase ownership changing — here's how the pipeline handles it without creating chaos.

Without deduplication logic
✗Steve, Julie, and Terry all receive the same email thread
✗Each labels it — three script fires, three new rows created
✗Status Sheet has 3 duplicate project records
✗Phase handoffs require manual communication of label names
✗Naming drift — "ClientA" vs "Client-A" vs "client a" across users
With thread ID deduplication
✓Gmail Thread ID is identical for all recipients of the same thread
✓Script checks Thread ID against Sheet before any write operation
✓Existing record: update only. New thread: create row. Never duplicate.
✓Phase fields per row — Live Action and Post each have their own owner and status
✓Phase handoff sends exact label name to incoming owner automatically
✓Self-serve lookup mode for anyone pulled in mid-project
The label as shared language: The intake tool generates the canonical label name from validated inputs — nobody types it manually. Every person on a project uses the same label string. That consistency is what makes thread ID matching work reliably across a distributed team.

ACERO note: The standardized project ID schema generated at intake is intentionally designed to map cleanly to ACERO project records. Phase 3 closes the loop between production tracking and financial reporting — validated savings from the pipeline become ACERO entries without manual re-entry.

Google I/O 2026

What Just Changed

Several announcements from Google I/O (May 19, 2026) and Cloud Next 2026 are directly relevant to this pipeline — some simplify the build, some validate the approach.

Available Now
Workspace Intelligence (GA)
Now generally available for enterprise customers. Provides a unified semantic context layer across Gmail, Docs, Drive — understanding relationships between projects, collaborators, and documents. Directly relevant to the email processing and status layer.
Available Now
Vertex AI → Gemini Enterprise Agent Platform
Vertex AI has been rebranded and expanded as the Gemini Enterprise Agent Platform — still the same underlying infrastructure this pipeline requires, now with more agent-native tooling including Agent Designer, trigger-based agents, and long-running agents built in.
Rolling Out Summer 2026
Gemini Spark + MCP
Gemini Spark is a persistent background agent integrated with Gmail, Docs, and Workspace. It expands to third-party tools via MCP this summer. If Spark matures for enterprise use, it could replace or simplify the custom email-watching layer of this pipeline entirely.
June 2026
Gemini 3.5 Pro
The heavier-weight Gemini 3.5 Pro model drops in June. Gemini 3.5 Flash is available today across all APIs. Either would power the intake conversation and email extraction layers of this pipeline with better reasoning than current models.
Bottom line: The custom build described in this document remains the right approach today — Spark and native agent tools aren't enterprise-ready yet. But the landscape is moving fast. Revisit the email processing and watcher layers once Spark's MCP integration ships this summer before building those components from scratch.
